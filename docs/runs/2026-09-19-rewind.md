# C5 / C6 — reverse operator + reversibility floor: code done, training BLOCKED

## What shipped (code, verified)

- `train --reverse` (commit `d7b8ab7`): flips the generator's time-axis
  order (mask/solver unchanged) so the model learns `state(t+1) ->
  state(t)`. Unit test `data::tests::reverse_flips_the_window_order` checks
  the reverse batch is the exact reverse of the forward batch at a fixed
  seed. `cargo test -p train -p jacobi2000` — 24/25 tests pass (see below
  for the one new test), `cargo clippy -p cli -p train -p jacobi2000` clean.
- `eval-metrics --reverse` (commit `d7b8ab7`): new
  `metrics::score_rollout_reverse` builds the forward solver truth
  trajectory once, then starts the reverse model at the LATEST recorded
  state and steps it backward, scoring against each earlier truth tick —
  the rewind score the goal doc asks for.
- `round-trip --forward --reverse` (commit `6dbed4b`): new
  `metrics::round_trip` steps a forward checkpoint N ticks then a reverse
  checkpoint N ticks back from a fresh single-drop state, and scores the
  result against the ORIGINAL state (corr, amplitude ratio, RMSE) —
  independent of either model's own forward accuracy, the round-trip number
  C6 asks for. Also reports `rmse(init, solver_forward_N(init))` as a scale
  for how far the physics itself moves in N ticks (the solver has no
  inverse, so this is a reference scale, not a literal floor).

All three compile clean (`cargo build -p cli`, dev and `--release`, both
default `ndarray` and `--features wgpu`) and are wired into the CLI exactly
as `docs/runs/*model20*` documents the forward flags.

## What is BLOCKED: actually training the three reverse checkpoints

Attempted: `train --steps 250 --lr 0.0001 --batch 16 --pool 64 --single-drop
true --long-fraction 0.2 --amplitude-max 0.3 --extra-drop-prob 0.3
--no-horizon-fraction 0.3 --extended-fraction 0.3 --rollout 8
--rollout-after 0 --noise 0.04 --lr-floor 1 --project true --project-energy
true --r-max 1.0001 --spectral 1 --nu 0 --seed 11 --layers 4 --dim 128
--mask stencil --radius 1 --dilation 1 --init artifacts/model19 --reverse
true --out artifacts/model20-reverse-nu0` (model20's own hyperparameters,
per this task's instruction to use model20's config; steps reduced from
model20's 700 to 250 to fit a ≤30-min budget at model20's own measured
~6.45 s/step from `docs/runs/2026-09-19-2.md`).

Backend: `wgpu` (Metal) — the M2's GPU was free of `llm-life train-a`/`t0`
processes at launch time (checked per the machine rule immediately before
launching).

**Result**: killed after 8m46s wall-clock having logged only step 1 of 250
(next log row is step 100 at `log_every=100`, hard-coded, not a CLI flag).
`ps` showed only 74s of CPU time consumed in that span (14% utilization) —
the process was alive and not panicking, just starved. Checked machine
load mid-run: `uptime` reported **load averages 52.17 34.46 22.01, 2 users**
on this M2, and a `pgrep` sweep found concurrent, unrelated, CPU/GPU-heavy
work from other sessions on this same laptop that started *after* my own
pre-launch check: a `t0-web` `wasm-pack build ... --features wgpu` (Metal),
a Python `dequant_gguf.py` run, and (separately, on the remote 3080 box via
ssh, not itself a violation) an `llm-life train-a` smoke run. A `cargo test
-p train` run that normally takes ~82s (per this task's own earlier timing)
took 278s under the same load.

This is a shared-machine contention problem, not a bug in `--reverse` or
`round-trip`: the code path that ran (step 1, loss `3.452410e-1`, finite)
is identical to the one `docs/runs/2026-09-19-2.md` ran successfully at
~6.5 s/step when the machine was quieter.

**Per this task's own machine rules** ("one GPU job at a time... never
report throughput under contention") and the project's global rule ("never
run two GPU jobs on the M2"), continuing to force this training through
under load-52 contention would produce numbers this doc could not stand
behind, and burning more wall-clock waiting on a starved process was not a
good trade against this run's own time budget. The job was killed rather
than left to (maybe) finish with a contended, unreportable wall-clock.
