# web/

The repo's demo page (`index.html` + `app.js`, WASM engine in `crates/web`).
Self-contained: copy this directory (plus a populated `model/`) to a static
server and it works. Follows the repo's demo template: no settings/URL panels
outside this gallery, verified headless.

## models in the gallery

`web/model/` is gitignored and regenerated by `tools/export_web_models.sh`,
which copies the checkpoint directories it is given (each holding
`model.safetensors` and `config.json`) and writes `web/model/index.json`,
which the model picker reads. Run it before opening the page locally:

```
./tools/export_web_models.sh model20=models/model20
```

`model-sph-smoke` loads in the browser (same tensor shapes as the shallow-water
checkpoints) but should only be run against SPH-splatted cases — running it
against the shallow-water solver produces the poor numbers above, not a bug.

Cases (`web/index.html`'s CASE picker): `drop` (click to place one, as
before), `dam_break` (a step in h across the domain, u = v = 0), `extended`
(two near-wall, high-amplitude drops matching the training run's own
`--amplitude-max`/`--extra-drop-prob` distribution) — CONCEPT.md sec. 6's
"generalization exhibit": every checkpoint here was trained on random
ripples, not these presets.

Compare mode runs two checkpoints side by side against the same solver
trajectory, corr/amplitude-ratio/wavefront-lag against the solver refreshed
every 10 ticks under each panel.
